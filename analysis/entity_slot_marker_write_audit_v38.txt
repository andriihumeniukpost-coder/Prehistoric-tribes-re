Dataflow finding and limitation
-------------------------------
The inventory confirms that bastore is widespread (1,492 instructions across the supplied disassemblies). A bastore instruction alone does not identify its target array: its array reference and index are stack operands, and the javap listing does not annotate those operands with source-level names. A rigorous attribution requires per-instruction JVM operand-stack dataflow, including aliases through locals and fields.

For the target buffer g.e, the strongest directly grounded lifecycle facts remain:
- Initialization: analysis/bytecode/f.txt, method private void i(), offsets 6–17: loads g.a, allocates new byte[9983] at offset 13, stores it into g.e at offset 15. Java newarray initializes all entries to 0.
- Allocation marker write: analysis/bytecode/g.txt, final byte a(byte, byte, byte, byte, byte), offsets 972–1002 per v37 audit: reads marker at 1919+slot and writes a computed marker to the same index.
- Release marker write: analysis/bytecode/g.txt, final void a(byte), offsets 230–240 per v37 audit: writes -1 to 1919+slot after e(slot), f(slot), before c(slot).
- The prior audit’s zero write in private boolean d(int) is e[808+i], not e[1919+i]; it is outside the marker region.

Range coverage
---------------
Marker indices are e[1919 + slot]. For the documented 1-based 50-slot allocator, the marker band is e[1920..1969]. This band is within the 9983-byte array. The complete bastore inventory is useful for narrowing candidates, but it does not by itself prove which writes can reach this band.

Conclusion (not overclaimed)
----------------------------
No confirmed reset path from -1 to 0 has been established by this pass. Nor is a slot leak proven: g.e is reallocated as a fresh zero-filled array by f.i(), but this excerpt does not establish when that initializer is invoked relative to scene transitions and active entities. To prove reuse failure, the remaining decisive work is operand-stack/index dataflow for all bastore instructions that can alias g.e, plus a call graph for f.i() and scene/reset entry points.

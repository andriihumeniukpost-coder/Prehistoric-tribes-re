Animation frame-parameter trace (static bytecode + /a table)
================================================================

1) State setup in g.S()
- ai is reset to 0; Z is reset to 0.
- d.a(ag) is called before the tables are read (state-dependent side effect).
- aS = unsigned(blob[offset(record 310) + ag]). This is the state's start index in the shared state-boundary table.
- am = signed byte blob[offset(record 311) + 229 + aS]. If ag==4 or am==0, that byte is overwritten with 27 and am becomes 27.
- ah = (unsigned(next boundary in record 310) - aS), stored as byte. This is the number of animation ticks/steps for the state interval; b(-1) increments ai until ai == ah-1, then calls U() instead.
- K boolean is set from am >= 27. Thus am values at/above 27 form a distinct behavior class in setup.
- aN is read from blob[offset(record 155) + 56 + am]. If aN==1, O() is called; otherwise K is decremented when K is false. This shows am indexes another behavior table, not merely a frame count.

2) Per-step reads in g.b(int)
- o = signed byte(blob[offset(record 154) + q]) + ai, narrowed to byte; it is a separate q-based sequence and should not be conflated with ag's state boundaries.
- aR = signed byte(blob[offset(record 311) + 229 + aS + ai]).
- aQ is set to -1 if blob[offset(record 155) + 84 + aR] is negative, else 0.
- aj = signed byte(blob[offset(record 311) + aS + ai]); ak = p[aj].
- al = signed byte(blob[offset(record 311) + 458 + aS + ai]); al is interpreted as a command/control code: >100 calls f(al,-2); ==99 calls f(p[0],-2); positive calls f(p[al],-2); ==-100 has a special case for ag==51 then calls f(-100,-2); other negative values call f(al,-3). Values 0 or -100 are treated separately.

3) Verified am==9 special case
U() checks am==9 before state-specific cases. When true it calls c.f() and jumps to shared cleanup, bypassing the branches for ag 28/34/38/44/48. The decoded states with raw am=9 are ag=18,26,29,35,53,54; state 4 is overridden to 27 regardless of its raw value.

4) Evidence boundaries
These are direct control/data-flow observations from decompiled bytecode and decoded resource /a. They identify the roles of fields and table offsets, but do not alone label states as walk/attack/jump etc. Visual naming needs call-site correlation or runtime/frame rendering evidence.

Entity-slot lifecycle v28 — bytecode audit
============================================

Scope
-----
Audited references to e[1919 + slot] in analysis/bytecode/g.txt. This is a static bytecode analysis, not a runtime trace.

Confirmed observations
----------------------
1. The field is used as a per-slot status/occupancy value for slot indices commonly checked from 1 through 50.
2. The code does NOT use one universal "free" test:
   - Several readers treat values <= 0 as inactive/free (if_le / ifgt branches).
   - The allocator in final void b(int,int) scans e[1919 + base + slot] until it finds a value exactly equal to 0; if no zero appears in 50 slots, it returns -1.
   - final void a(byte) writes -1 to e[1919 + slot] before calling c(slot), which is evidence of a removal/deactivation path.
3. private void aj() advances field l while e[1919 + l] <= 0, then sets Q=true when it finds an active positive slot. This is a search for a live entry, not allocation.
4. private void q() uses a positive status value to gate a large processing branch for the current an slot. It then reads other parallel e[] fields, including offsets 4444, 6767 and related tables, indicating that the marker gates further per-slot processing.
5. private void ad() loops over active slots (1..50) and checks e[1414 + slot] against threshold 12 in two separate branches. This links activity to a second per-slot field but does not by itself establish that field's meaning.
6. Because tests differ (==0 vs <=0), do not describe every non-positive value as identical across all methods. In particular, -1 is explicitly written on one removal path, while one allocator requires exactly 0.

Method evidence
---------------
- final void a(byte): writes e[1919 + slot] = -1, then calls f(slot), c(slot), and continues cleanup.
- final void b(int,int): scans 50 entries for e[1919 + base + slot] == 0; returns -1 if no exact-zero slot is found.
- private void aj(): increments l while e[1919 + l] <= 0; sets Q=true after reaching a positive entry.
- private void q(): gates slot processing on e[1919 + an] > 0.
- private void ad(): scans active slots and checks e[1414 + an] against 12.

Interpretation limits
---------------------
The table is best described as a status/occupancy marker, but a complete state machine requires tracing every write to this offset and the values assigned. Do not infer object class (enemy/projectile/effect) from this marker alone.

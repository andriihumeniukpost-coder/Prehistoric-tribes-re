Animation coordinate normalization — bytecode-confirmed

Method g.aK()V copies base coordinates:
  y = C
  A = D

It then normalizes offsets I and K:
1. If I is negative, increment it until zero.
2. If K is negative, increment it until zero, except when flag s is true (then the loop stops and K may remain negative).
3. Enforce I + O <= c.S by decrementing I as needed.
4. Enforce K + P < d - 1 by decrementing K as needed.

This is direct bytecode behavior, not a visual guess. It shows I and K are bounded offsets relative to base coordinates C/D, with upper limits dependent on O/P and object dimensions c.S and d. The special s flag changes handling of negative K.

Important correction to interpretation: this method does not itself draw anything. It normalizes coordinate/state fields, and is called from several gameplay/animation paths. To establish exact screen axes and sprite placement, correlate assignments of C/D, O/P, and the actual Graphics draw calls.

Evidence: g.txt, method private void aK(), offsets 0–130. No original game code was modified.
